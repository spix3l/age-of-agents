# D8-06 — Player-versus-player

[Back to EPIC-08](../epics/EPIC-08-depth.md) · [Backlog index](../../BACKLOG.md)

**Outcome:** Two people can play each other.

**Status:** `DEFERRED` by the project owner on 2026-09-04 ("skip for now").

Recorded so the decision is not lost. The open question is scope, because it
determines whether this fits the architecture at all:

- **Local two-player on one machine** reuses the command layer as-is and keeps
  the static-bundle constraint. Smallest real version.
- **Peer-to-peer over WebRTC** needs no game server but still needs a hosted
  signalling service, deterministic lockstep, and desync handling.
- **An authoritative backend** breaks the no-backend constraint the whole
  project is built on.

Nothing in Epic 08 should foreclose any of these. In particular, keep every
player action flowing through `src/game/commands/` and keep `MatchSimulation`
free of presentation state, because that is what a lockstep or hotseat mode
would have to build on.
